# 저장 안 된 채팅 복구

답변은 받았는데 채팅이 저장되지 않아, 새로고침하거나 서버를 다시 켜면 사라졌을 때 쓰는 방법입니다.

## 되는 이유

서버는 AI에 보낸 요청과 받은 응답을 `save/request-logs.db`에 따로 남깁니다. 채팅 저장이 실패해도 이 기록은 남습니다.

- 마지막 요청의 프롬프트에는 그때까지의 대화가 저장본과 글자 하나까지 똑같이 들어 있습니다. 빠지는 것은 `<Thoughts>` 생각 블록뿐입니다.
- 각 답변은 그 답을 만든 요청의 응답 기록과 맞춰서 생각 블록과 메시지 ID를 되찾습니다.
- 마지막 답변은 마지막 요청의 응답 원문에서 가져옵니다.

2026-09-24 사고로 확인했습니다. 이미 저장돼 있던 답변들을 이 방법으로 다시 만들어 보니 저장본과 똑같았습니다.

## 필요한 것

- **그 대화를 처리한 서버의 `save` 폴더가 있어야 합니다.** 노트북 서버에서 한 대화라면 노트북에서 돌려야 합니다.
- **빨리 돌려야 합니다.** 요청 기록은 본문이 총 256MB를 넘으면 오래된 것부터 지워집니다. 생성 한 번에 약 60KB라 수천 번 분량이 남습니다.

## 하는 법

1. 서버 폴더(PocketRisu)에서 실행합니다. 서버는 켜둔 채로 돌려도 됩니다. 서버 파일은 읽기만 합니다.

   ```bash
   node tools/recover-chat-from-request-logs.cjs --since 6h
   ```

   - `--since`는 "몇 시간 전부터" 또는 `2026-09-26T15:00:00+09:00` 같은 시각입니다. 사라진 첫 대화보다 조금 이전으로 잡아야 첫 요청까지 포함됩니다.
   - `--until`로 끝 시각도 정할 수 있습니다.
   - `--dry-run 1`을 붙이면 파일을 만들지 않고 무엇을 찾았는지만 보여줍니다.
   - 이 PC에서는 `node` 대신 `H:\NodeJs\node.exe`를 씁니다.

2. `recovered-chats/` 폴더에 `캐릭터 - 채팅 (복구).json` 파일이 생깁니다. 저장본보다 더 진행된 요청 기록이 있는 채팅마다 하나씩 만들어집니다.

3. 앱에서 그 캐릭터를 열고, 채팅 목록의 **채팅 불러오기**로 파일을 고릅니다. "채팅 이름 (복구)"가 새 채팅으로 생기고, 기존 채팅은 그대로 남습니다.
   - 출력에 `[deactivated]`가 붙은 캐릭터는 비활성 상태입니다. 먼저 활성화하고 불러오세요.

## 한계

- **마지막 답변은 모델이 보낸 원문입니다.** 봇 스크립트(Lua)가 답을 받은 뒤 고치는 부분은 다음 턴이나 리롤 때 다시 적용됩니다. 상태줄을 보조 모델로 다시 계산하는 봇이라면 상태줄 한 줄이 다를 수 있습니다.
- **요청 기록에 없는 것은 되살릴 수 없습니다.** 손으로 고친 메시지, 지운 메시지, AI를 부르지 않은 편집이 여기에 해당합니다.
- **봇 스크립트 변수는 저장본 시점 값입니다.** 장소, 시간 같은 값이며 다음 턴에 다시 계산됩니다.
- 도구가 판단하지 못하면 그 채팅은 `NOT rebuilt`로 이유를 보여주고 건너뜁니다. 봇이 프롬프트 끝에 지시문을 여러 개 붙이는 경우 등입니다.

## Claude에게 맡길 때

"`tools/recover-chat-from-request-logs.cjs`로 ○시부터 사라진 채팅 복구해줘"라고 하면 됩니다.
