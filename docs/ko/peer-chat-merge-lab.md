# 두 서버 채팅 병합 실험

이 문서는 데스크톱과 노트북의 **독립적인 PocketRisu 서버**를 번갈아 사용할 때 필요한 병합의 첫 실험을 기록합니다. 현재 코드는 `server/node/peer-chat-merge.cjs`의 순수 병합 함수와 격리된 시험뿐입니다. 실제 서버 사이에 전송하거나 주기적으로 동기화하는 기능은 **아직 연결되지 않았습니다**.

## 시험한 규칙

- 같은 캐릭터 ID가 양쪽에 있을 때, 한쪽에만 있는 채팅방은 다른 쪽에 추가합니다.
- 같은 채팅방 ID의 내용이 다르면 어느 원본도 덮어쓰지 않고 상대 버전을 `peer-preserved-*` ID의 별도 채팅방으로 보존합니다.
- 같은 상태로 다시 실행해도 보존 채팅방이 계속 늘어나지 않습니다. 한쪽 저장만 성공한 뒤 재시도해도 결과가 복구됩니다.
- 캐릭터 자체가 한쪽에만 있으면 옮기지 않습니다. 캐릭터의 에셋·모듈 의존성이 함께 전송되지 않았기 때문입니다.
- 설정, API 키, 플러그인, 모듈, 에셋, 캐릭터 본문은 병합하지 않습니다.
- 전체 채팅 본문이 없는 `_stub`이나 중복 ID는 거부합니다.

`server/node/peer-chat-merge.test.ts`는 서로 다른 임시 SQLite 파일 두 개에서 시험합니다. 이 파일은 작은 JSON 시험 데이터를 담으며, 실제 PocketRisu의 청크형 `database.bin` 인코딩·실시간 저장 경로·네트워크 송수신까지 검증한 것은 아닙니다.

```powershell
node_modules\.bin\vitest.cmd run --configLoader runner --config vitest.config.server.ts server/node/peer-chat-merge.test.ts
```

## 실제 서버 사용 전 필요한 것

1. 노트북과 데스크톱 각각의 `save`를 안전하게 스냅샷으로 보관합니다. 라이브 SQLite 파일을 단순 복사하는 대신 서버를 멈추거나 SQLite 백업 절차를 사용합니다.
2. 각 서버의 고유 ID와 인증된 전송 경로를 만들고, 채팅 변경분을 내구성 있게 기록합니다.
3. 최초 상태를 비교한 뒤 변경분만 주고받고, 적용 확인 후에만 커서를 전진시킵니다. 네트워크 끊김·재시작·한쪽 적용 실패를 재시도합니다.
4. 캐릭터·모듈·에셋을 어떻게 옮길지 별도로 정합니다. 채팅만 동기화한 상태를 전체 서버 동기화로 표시하지 않습니다.
5. 두 실제 서버를 복제한 시험 데이터에서 왕복·동시 수정·충돌 보존·용량을 검증한 뒤에만 활성화합니다.

따라서 현재 데스크톱 서버에서 채팅하면 그 내용은 **데스크톱에만 저장**됩니다. 나중에 노트북으로 자동 이월된다고 가정해서는 안 됩니다. 채팅 복구 도구 역시 해당 요청을 처리한 서버의 `request-logs.db`만 읽습니다.
