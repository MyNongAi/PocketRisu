# 외부 에셋 저장소

PocketRisu는 캐릭터와 모듈의 이미지 바이너리를 Risu DB 밖에 둘 수 있습니다. DB에는 에셋 이름, SHA-256 해시, 크기, 공급자 ID와 같은 작은 매핑만 남고, 참조는 다음 형식을 사용합니다.

```text
external://provider-id/sha256-hash
```

채팅에서는 이미지가 실제로 필요한 순간에만 서버의 지연 로딩 URL을 사용합니다. 원본 바이트는 마이그레이션 검증이나 호환 익스포트처럼 꼭 필요한 작업에서만 읽습니다.

## 저장소 공급자 선택

고급 설정의 **External asset storage (PocketRisu core)**에서 공급자를 설정합니다.

| 공급자 | 용도 | 주의점 |
| --- | --- | --- |
| 앱 로컬 파일시스템 | 기본값. PocketRisu 작업 폴더 기준 `save/external-assets/store`에 저장 | 가장 간단하며 PocketRisu의 일반 업데이트 경로에 보존됨 |
| 사용자 지정 파일시스템 | 다른 드라이브, NAS 마운트 또는 Termux가 접근할 수 있는 공유 폴더 | 폴더 권한과 경로를 사용자가 관리해야 함 |
| HTTP | 서버가 `base-url/<sha256>`에 `GET`과 `PUT` 요청 | 마이그레이션에는 쓰기 가능한 엔드포인트 필요. 인증 헤더는 PocketRisu 서버에만 저장됨 |
| Android SAF | 현재 미지원 | 아래 설명 참고 |

PocketRisu의 Android 실행 방식은 네이티브 앱이 아니라 **Termux의 Node 서버 + 브라우저**입니다. 따라서 SAF 폴더 선택기, 영구 URI 권한, 문서 공급자 스트림을 연결할 네이티브 브리지가 없습니다. 현재는 `termux-setup-storage`로 허용한 공유 폴더 등 Termux가 일반 파일 경로로 접근할 수 있는 위치를 사용하세요.

## 안전한 마이그레이션

원본을 먼저 백업한 뒤 다음 순서를 지키는 것을 권장합니다.

1. **Scan**으로 캐릭터와 모듈의 참조 수, 고유 에셋 수, 용량, 누락 파일을 확인합니다.
2. **Migrate safely**를 실행합니다. PocketRisu는 외부 저장소로 복사한 뒤 다시 내려받아 해시와 크기를 검사합니다.
3. 성공하면 DB 참조가 한 번에 `external://...`로 바뀌고 페이지가 다시 로드됩니다. 모든 준비가 성공하기 전에는 기존 참조를 바꾸지 않습니다.
4. 내부 원본은 즉시 영구 삭제되지 않고 `save/external-assets/trash`에 복구 가능한 상태로 남습니다.
5. **Verify again**으로 외부 파일을 다시 내려받아 검사하고, 캐릭터와 모듈을 직접 열어 확인합니다.
6. 사용자가 확인한 뒤에만 **Purge verified trash**를 실행합니다. 검증되지 않은 항목은 삭제가 거부됩니다.

마이그레이션 도중 실패하면 기존 DB 참조와 내부 에셋은 유지됩니다. 이미 복사된 외부 파일이 남을 수는 있지만 기존 데이터가 그것을 가리키도록 게시되지는 않습니다.

## 채팅의 최근 출력만 렌더링

고급 설정의 **Asset render window**는 현재 채팅 페이지에서 실제 미디어 URL을 해석할 최근 캐릭터 출력 수입니다.

- 기본값은 `5`입니다.
- `0`은 제한 없음으로, 이전과 같이 모든 출력의 에셋을 렌더링합니다.
- 범위 밖 메시지는 텍스트를 유지하지만 `{{asset}}`, `{{image}}`, `{{emotion}}` 등의 파일 URL을 요청하지 않습니다.
- 새 출력이 추가되어 범위에서 벗어난 미디어는 DOM에서 제거되고 Object URL과 디코딩 메모리가 해제됩니다.

큰 채팅을 열 때 모든 과거 이미지를 한꺼번에 읽지 않으므로 네트워크, 메모리와 디코딩 비용을 줄일 수 있습니다.

## 백업과 다른 컴퓨터로 이동

PocketRisu 기본 백업에는 외부 에셋 원본 대신 작은 manifest가 포함됩니다. manifest에는 `external://` 매핑과 검증 정보가 들어가지만 공급자 인증 정보나 전체 이미지 바이너리는 포함되지 않습니다.

다른 컴퓨터에서 복원하려면 다음 두 가지를 모두 준비해야 합니다.

1. 기본 백업을 가져옵니다.
2. 에셋 폴더를 별도로 복사하거나 같은 HTTP 저장소를 사용하고, **동일한 provider ID**를 새 PocketRisu의 경로 또는 base URL에 연결합니다.

provider ID가 다르면 manifest가 저장소를 찾을 수 없습니다. 로컬 경로는 컴퓨터마다 달라도 되지만 manifest가 참조하는 ID는 같아야 합니다.

원본 RisuAI와 호환되는 upstream 익스포트를 선택한 경우에만 외부 파일을 그때 내려받아 백업 안에 실제 바이트를 넣습니다. 따라서 이 익스포트는 기본 PocketRisu 백업보다 크고 느릴 수 있습니다.

## 장애와 캐시

외부 요청은 설정한 횟수만큼 재시도됩니다. 외부 저장소가 실패하면 PocketRisu는 보관된 휴지통 사본과 남아 있는 내부 파일을 차례로 확인하며, 모두 실패한 경우 채팅에 로드 오류를 표시합니다.

서버의 바이트 캐시는 크기가 제한된 메모리 LRU입니다. 오래된 항목은 자동으로 제거되며 전체 외부 저장소를 다시 로컬 캐시로 복제하지 않습니다. 캐시 한도와 재시도 횟수는 같은 고급 설정에서 조정할 수 있습니다.
