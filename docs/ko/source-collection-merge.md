# 출처별 봇·모듈·페르소나 병합

PocketRisu는 전체 데이터베이스를 덮어쓰지 않고 여러 Risu 환경의 봇, 모듈, 페르소나만 모으는 컬렉션 형식을 지원합니다.

## 구성

- 송신기: 공식·로컬·모바일 웹 Risu에 설치하는 API v3 플러그인
- 수신기: PocketRisu의 `설정 → 마이그레이션 → 출처별 컬렉션 병합`
- 표시: 캐릭터와 모듈은 `[출처] 이름` 폴더, 페르소나는 카드 배지

플러그인은 채팅과 플러그인 자체를 내보내지 않습니다. 이름이 같은 항목도 자동으로 합치거나 삭제하지 않으며, PocketRisu가 새 ID를 발급하여 모두 보존합니다.

## 형식과 안전성

- `*.risu-characters`: 봇과 참조 에셋
- `*.risu-modules`: 모듈과 참조 에셋
- `*.risu-personas`: 페르소나·내장 모듈과 참조 에셋
- 모바일 기본 조각 크기: 12MB
- 모바일 안전 한도: part 32MB, 단일 에셋 16MB
- 에셋 검증: SHA-256과 바이트 크기
- 참조 검증: 엔티티가 가리킨 에셋과 실제 포함된 에셋 목록이 정확히 일치해야 함
- 중단 감지: 마지막 part 표시가 없는 묶음은 가져오지 않음
- 적용 순서: 모든 part 검사 → 에셋 검증·저장 → 참조 재작성 → DB 병합·저장

에셋 처리 중 실패하면 기존 DB는 변경하지 않습니다. 이미 저장된 동일 해시 파일은 무해한 미참조 파일로 남을 수 있으며, 에셋 진단 기능에서 정리할 수 있습니다.
가져오기 파일은 하나씩 읽고 검증한 뒤 놓아주므로 모든 base64 원본을 한꺼번에 메모리에 올리지 않습니다. 선언된 크기와 base64 길이가 맞지 않거나 JSON 깊이·항목 수가 비정상적인 파일은 디코딩 전에 거부합니다.

16MB를 넘는 단일 원본은 모바일 브라우저가 JSON 문자열·base64·디코딩 바이트를 동시에 보유하다 종료될 위험이 있어 이 플러그인으로 내보내지 않습니다. 그런 파일은 별도로 보관하거나 먼저 합리적인 이미지 크기로 줄여야 합니다.

## 사용 순서

1. PocketRisu 마이그레이션 화면에서 내보내기 플러그인을 받습니다.
2. 데이터를 가져올 각 Risu에 플러그인을 설치합니다.
3. 출처 이름을 `로컬리스`, `모바일웹리스`, `PC웹리스`처럼 지정합니다.
4. 봇·모듈·페르소나 버튼을 각각 누릅니다.
5. 생성된 part 파일을 종류별로 빠짐없이 PocketRisu에 가져옵니다.

브라우저가 여러 파일 다운로드 권한을 요청하면 허용해야 합니다. 일부 part만 복사하거나 서로 다른 묶음의 part를 섞으면 수신기가 거부합니다.

플러그인은 공식 Risu의 공개 API v3인 `getDatabase()`, `readImage()`, `registerSetting()`만 사용합니다. 해당 설정 항목이 나타나지 않는 오래된 로컬·웹 클라이언트라면 최신 API v3 지원판으로 업데이트한 뒤 사용해야 합니다.
