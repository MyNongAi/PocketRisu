# PocketRisu 개조판 한눈에 보기

공식 PocketRisu v1.12.0을 기반으로, 캐릭터·모듈·에셋이 아주 많은 환경에서도 덜 느리고 안전하게 사용할 수 있도록 고친 개인 개조판입니다.

## 한 줄 소개

**수십만 개의 에셋과 수백 개의 캐릭터를 가진 대형 Risu 환경을 위해 저장소, 이미지 로딩, 목록 렌더링과 채팅 메모리를 가볍게 만든 PocketRisu입니다.**

## 쉽게 보는 변경점

- **이미지 원본 분리** — 거대한 이미지 파일을 PocketRisu DB 밖의 다른 드라이브나 원격 저장소에 둘 수 있습니다.
- **안전한 에셋 이전** — 복사·해시 검증·복구용 휴지통 확인이 끝난 뒤에만 참조를 바꿉니다.
- **작은 썸네일 사용** — 목록에서는 원본 대신 작은 WebP 썸네일을 사용해 로딩과 메모리 사용을 줄였습니다.
- **원본은 필요할 때만** — 이미지를 확대하거나 다른 앱으로 드래그할 때만 원본 파일을 불러옵니다.
- **보이는 항목만 렌더링** — 에셋·캐릭터·높이가 제각각인 모듈이 많아도 화면 주변의 항목만 실제로 만들어 멈춤과 튕김을 줄였습니다.
- **채팅 메모리 제한** — 최근에 사용한 채팅만 메모리에 유지하고 오래된 채팅은 작은 자리표시자로 되돌립니다.
- **빠른 채팅 전환** — 자주 여는 최근 채팅을 미리 준비하고, 짧은 로딩에는 불필요한 로딩 화면을 띄우지 않습니다.
- **두 채팅 안전 병행** — 서로 다른 채팅 두 곳까지 동시에 답변을 받을 수 있고, 시작할 때의 채팅·페르소나·모델 경로를 고정해 화면을 옮겨도 응답이 섞이지 않습니다.
- **PC 분할 채팅** — 좌측 메뉴의 두 패널 버튼으로 보조 채팅을 열고, 서로 다른 캐릭터·채팅을 한 화면에서 선택해 동시에 요청할 수 있습니다. 가운데 바는 양끝에 가깝게 옮기거나 더블클릭해 반반으로 되돌릴 수 있고, 사용자 CSS의 고정 버튼도 좌우 작업영역을 벗어나지 않습니다.
- **여러 캐릭터 비차단 가져오기** — 선택한 파일을 안전하게 순차 저장하면서 모든 작업의 진행표시를 함께 보여 주며, 처리 중에도 채팅과 다른 조작을 계속할 수 있습니다.
- **최근 사용 순 정렬** — 최근에 열거나 가져온 캐릭터와 최근에 활성화한 모듈을 위에서 찾을 수 있습니다.
- **안정적인 봇·폴더 드래그** — 화면상의 임시 번호 대신 캐릭터·폴더 ID로 이동하므로 검색·정렬 도중에도 엉뚱한 항목을 옮기지 않으며, 순수 변환 시험으로 폴더 안팎 이동을 보호합니다.
- **모듈 편집 지연 제거** — 글자를 입력할 때 모든 모듈을 반복 검사하지 않고, 완료할 때 변경된 모듈만 저장합니다.
- **순서를 보존하는 모듈 폴더** — 원본 모듈 배열은 건드리지 않고 폴더만 겹쳐 표시하며, 폴더를 삭제해도 안의 모듈은 남습니다.
- **큰 모듈 목록 가상화** — 설명과 폴더 선택창의 실제 높이를 재면서 보이는 행만 유지해, 모듈이 많아도 편집 화면이 가벼워집니다.
- **페르소나 이미지 드롭** — 원하는 페르소나 카드에 이미지를 바로 끌어놓아 바꾸고, 실제 이미지 형식과 저장 대상을 검증합니다.
- **조절 가능한 페르소나 정보창** — 하단 정보창을 작게 줄이고, 화면 안에서 이동·크기 조절·접기·원위치 복원이 가능하며 배치를 기억합니다.
- **설정 메뉴 사용자 정렬** — 설정 왼쪽 메뉴를 드래그·길게 누르기·키보드로 원하는 순서에 놓을 수 있습니다.
- **동작 버튼 양쪽 배치** — 채팅과 모듈의 주요 버튼을 위와 아래에서 모두 사용할 수 있습니다.
- **출처별 이전 도구** — 웹리스·로컬리스·모바일리스에서 캐릭터·모듈·페르소나를 따로 내보내고, 덮어쓰지 않은 채 출처 폴더와 배지로 구분해 합칩니다.
- **에셋 진단과 안전 복구** — 모든 참조의 존재·크기를 검사하고 일부 원본의 해시·이미지 디코딩을 확인하며, 같은 해시의 복구본이 있을 때만 외부 객체를 되살립니다.
- **업데이트 친화적 구조** — 공식 PocketRisu 업데이트를 포함한 Git 브랜치 위에 기능별 변경을 나눠 관리합니다.

## 두 채팅 동시 요청의 범위

기존 PocketRisu 계열에도 채팅별 생성 상태와 채팅별 정지 버튼의 기반은 들어 있지만, 실제 전송 진입점에는 전역 생성 잠금이 남아 있어 두 번째 채팅 요청은 막혔습니다. 이 개조판은 그 전역 잠금을 채팅별 원자적 점유로 바꾸고 다음 규칙을 적용합니다.

- 같은 브라우저에서 서로 다른 채팅은 최대 2개까지 병행합니다.
- 같은 API를 쓰는 두 채팅과 서로 다른 API를 쓰는 두 채팅을 모두 허용합니다.
- 같은 채팅의 중복 요청은 1개로 제한합니다.
- 캐릭터·채팅·페르소나·모듈·정규식/CBS·Lua·모델 경로를 요청 시작 시점 기준으로 전달합니다.

이는 **한 클라이언트의 분할 화면뿐 아니라 PC·폰처럼 서로 다른 클라이언트의 생성 작업도 채팅 단위로 격리**합니다. 서버는 채팅별 작성 임대와 저장 전 ETag 검사를 사용하므로 서로 다른 채팅 A/B는 함께 진행할 수 있고, 같은 채팅 A/A의 두 번째 요청만 막습니다. 저장 직전에 다른 기기의 최신 변경과 다시 합치므로 한 기기의 오래된 전체 DB가 다른 채팅의 새 응답을 덮어쓰지 않습니다. 다만 같은 캐릭터 설정이나 같은 메시지를 두 기기에서 동시에 편집하는 범용 실시간 공동 편집까지 제공하는 것은 아닙니다. 또한 타사 플러그인이나 일부 로컬 모델 공급자가 자체적으로 동시 요청을 지원하지 않으면 그 공급자 쪽 제한은 그대로 적용됩니다.

## 성능 확인 사례

- 약 47GB 규모의 실제 사용자 DB에서 에셋 이전 계획 분석 시간을 약 611초에서 36초로 줄였습니다.
- 약 54만 개의 에셋 참조와 약 49만 개의 고유 에셋을 대상으로 검사했습니다.
- 깨진 에셋 참조가 있어도 정상 파일의 이전 계획 전체가 중단되지 않도록 바꿨습니다.

측정 뒤에도 데이터가 계속 추가되고 있으므로 위 숫자는 고정 사양이 아니라 당시의 기준값입니다.

## 실사용 현황과 남은 작업

- 완료: 공식 v1.12.0과 개조 기능 계약을 통합한 빌드를 검증하고 C 드라이브 실사용 서버에 배포
- 완료: 약 47GB의 기존 에셋을 C 드라이브에서 H 드라이브 외부 저장소로 복사하고 해시·크기를 검증한 뒤 참조를 전환
- 보존 중: 이전 원본은 사용자 확인 전 영구 삭제하지 않고 복구용 휴지통에 유지
- 확인 필요: 로컬리스·PC 웹리스·모바일 웹리스에서 만든 출처별 컬렉션의 사용자 검수와 중복 정리
- PC·폰 동시 편집이 필요하면 채팅·캐릭터·설정을 레코드별 revision으로 저장하고 충돌을 병합하는 다중 작성자 동기화 계층 추가

## 권장 설치 배치

- **C 드라이브 SSD** — 실제 PocketRisu 실행본, SQLite DB, 자주 쓰는 작은 썸네일 캐시
- **H 드라이브 HDD** — 용량이 큰 이미지 원본
- **메모리·브라우저 캐시** — 최근에 본 일부 데이터만 크기를 제한하여 임시 보관

Git 작업 이력과 실사용 소스는 C 드라이브 저장소에서 관리하고, 대용량 이미지 원본은 H 드라이브 외부 저장소에 둡니다. 약 47GB의 기존 에셋은 해시·크기 검증과 참조 전환을 완료했으며, 복구용 원본의 영구 삭제만 사용자 검증 뒤로 보류했습니다.

## 공식 PocketRisu에 제안하기 좋은 기능

1. 썸네일 캐시와 원본 드래그 전환
2. 대형 목록 가상화
3. 모듈 편집 렉 제거
4. 비차단 다중 캐릭터 가져오기 진행 UI
5. 안전한 채팅 메모리 LRU
6. 측정형 모듈 목록 가상화
7. 출처별 캐릭터·모듈·페르소나 병합 형식
8. 읽기 전용 에셋 진단과 동일 해시 복구

외부 에셋 저장소는 저장 형식·백업·복구 정책까지 바뀌므로, 먼저 구조 제안 문서를 합의한 뒤 작은 PR로 나누는 편이 안전합니다.
