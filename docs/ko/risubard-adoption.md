# RisuBard 성능 철학 이식 장부

## 비교 기준

- RisuBard: commit `b4fc3810` (2026-09-22 확인)
- HaejeokRisu: commit `6c52c34b` (2026-09-23 확인)
- 대상: 공식 PocketRisu `v1.12.0` 위 `feature/external-assets`

저장 엔진을 통째로 바꾸지 않고, 상류 PocketRisu를 계속 따라갈 수 있는 작은 경계만 가져옵니다. RisuBard의 파일 중심 canonical 저장소·저널·revision·휴지통과 HaejeokRisu의 PostgreSQL/RustFS 배치는 각각 완결된 별도 저장 철학이므로 `database.bin` 호환 브랜치에 반쪽만 섞지 않습니다.

## 이식한 경계

1. **필요 화면만 동적 import**
   - 설정, 캐릭터 관리자, 프리셋, 페르소나·메모리 목록, 에셋 뷰어와 프로톤 브라우저를 최초 번들에서 분리합니다.
   - 한 번 불러온 컴포넌트는 캐시하여 다시 열 때 재요청하지 않습니다.

2. **이미 정규화된 캐릭터 재순회 생략**
   - 캐릭터를 열 때마다 모든 로어북과 모든 채팅을 변환하지 않습니다.
   - 런타임 필수값이나 구형 lorebook이 남은 카드만 기존 `characterFormatUpdate()`를 실행합니다.

3. **편집 초안과 canonical DB 분리**
   - 모듈 텍스트 입력은 분리된 초안에서만 반응합니다.
   - 저장할 때 한 번 실DB에 넣어 대형 lorebook·asset 배열의 깊은 감시가 키 입력마다 깨어나는 것을 막습니다.

4. **제한형 작업 집합 유지**
   - 캐릭터·에셋 이미지 URL은 LRU 한도 안에서만 유지합니다.
   - 채팅은 최근 범위와 현재 화면 근처 메시지만 에셋 URL을 해석합니다.
   - 화면 밖으로 밀린 채팅 미디어는 DOM 소스·Object URL·디코딩 메모리를 해제합니다.

5. **중복 인증 확인 병합**
   - 여러 화면이 동시에 서버 작업을 시작해도 `/api/test_auth` 확인은 한 번만 보냅니다.
   - 실패는 캐시하지 않아 네트워크가 돌아온 다음 요청이 정상 재시도할 수 있습니다.

## 통째로 가져오지 않는 항목

- RisuBard의 파일 canonical 저장소와 HaejeokRisu의 관계형 SQL 저장소는 현재 PocketRisu 백업·플러그인·모바일 데이터 형식과 직접 호환되지 않습니다.
- 서버 페이지네이션 API 없이 UI 코드만 베끼면 결국 전체 `database.bin`을 받은 뒤 잘라 보이는 장식에 불과하므로 도입하지 않습니다.
- 에셋 해시는 제거하지 않습니다. 해시는 렌더링 캐시가 아니라 중복 판별, 무결성 검증, Realm 복구 매칭용 식별자입니다.

## 다음 안전 후보

- 캐릭터 shadow index: 이름·폴더·최근 시각·소형 썸네일만 먼저 받고 본문은 선택 시 수화합니다.
- 바이너리 에셋 묶음 업로드: 메타데이터 저장과 분리하되 재시도·해시 검증·부분 실패 원장을 먼저 둡니다.

이 후보들은 저장 경계를 건드리므로 현재 UI 성능 수정과 같은 커밋에 억지로 섞지 않습니다.
